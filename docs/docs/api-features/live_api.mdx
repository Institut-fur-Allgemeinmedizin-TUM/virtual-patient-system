# Live Websocket API

The live feature is the most important non-HTTP API in the system. It connects the client to the backend over a
websocket and forwards all relevant information to Gemini Live API.

While all the other chat messages are sent to an LLM via the Langchain Project (for easy interchangability of backend
models), this fully relies on the google-genai python library.

## Endpoint

`/api/live/{session_id}/ws`

The client opens this websocket using the same session cookie that is used for the HTTP API.

## What the websocket does

The websocket is a relay:

1. authenticates the user
2. checks that the session exists and belongs to that user
3. checks that live time is still available
4. connects to Gemini Live with the session prompt and previous history
5. forwards microphone input to Gemini Live
6. forwards transcript and audio output back to the client
7. stores transcript content in the database when available

## Client to server messages

The client sends JSON messages to the websocket.

### Audio chunks

```json
{
  "type": "audio",
  "data": "<base64 PCM16 payload>",
  "mime_type": "audio/pcm"
}
```

Binary websocket frames are also accepted by the backend and forwarded as raw PCM audio.

### Text input

```json
{
  "type": "text",
  "text": "Some text message by the user"
}
```

Text is stored as a user message and forwarded to Gemini Live as realtime text input (this is needed that the model
still answers with audio rather than only answering by text).

### End turn signal

```json
{
  "type": "end_turn"
}
```

Finalizes the current turn.

## Server to client messages

The backend sends JSON event objects back to the client.

### Assistant text

```json
{
  "type": "model_text",
  "text": "..."
}
```

This sends the transcript of the LiveAPI directly to the user (realtime).

### Assistant audio

```json
{
  "type": "model_audio",
  "mime_type": "audio/pcm",
  "data": "<base64 PCM16 payload>"
}
```

Contains the audio chunks for the client.

### User transcript

```json
{
  "type": "user_text",
  "text": "..."
}
```

To also display the user voice input the user transcript is also relayed to the client.

### Errors

```json
{
  "error": "no live time remaining"
}
```

Errors are also sent as JSON with the error message included.

## Connection requirements

The backend rejects or closes the websocket when one of the following is true:

- the user is not authenticated
- the session does not exist
- the session belongs to another user
- the session is a VHB session
- Gemini Live is not configured on the backend
- the Gemini client library is not available
- the session has no live time left

## Session history and resume support

Before opening the Gemini Live stream, the backend loads previous messages from the session and seeds
them into the live context.

If Gemini returns a resumable handle, the backend stores that handle in `sessions.live_api_handle` for later use.
This for example could be used for evaluating the conversation even better (requires a multimodal output model from
google which is not yet available)

## Time accounting

Live mode is limited by two checks:

- per-session remaining live time (max 10 minutes)
- total daily usage for the user (max 30 minutes)

The session starts with the default live budget from the model layer.
When the websocket session ends, the elapsed time is subtracted from the session budget.

This e.g. enables for higher defaults for specific users.

## Notes for client implementers

- Keep the websocket open only while the user is actively in live mode.
- Send `end_turn` before closing if you want the model to finish the current response cleanly.
- Treat `model_text` and `user_text` as transcript events, not as authoritative conversation history.
- Buffer audio playback on the client side; Gemini Live sends small chunks.
