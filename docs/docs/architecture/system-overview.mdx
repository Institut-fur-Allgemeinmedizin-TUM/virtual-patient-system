# System Overview

The Virtual Patient System is a medical training platform for anamnesis practice.
It combines a FastAPI backend, a web frontend, and a mobile app that allows the student to talk to a virtual patient.

## Main parts

- Backend: FastAPI application in `app/`
- Mobile and Web client: Expo app in `mobile/`
- Documentation: Docusaurus site in `docs/`

## Runtime responsibilities

The backend owns the conversation state, session persistence, authentication, and integration with the LLM providers.

The frontend and mobile app are responsible for user interaction only.

## Request flow

1. A user authenticates with either TUM SSO or the VHB login flow.
2. The client creates a session for a selected case.
3. Text chat requests are sent to the regular HTTP API.
4. When live mode is enabled, the client opens a websocket for the session.
5. The backend streams microphone input to Gemini Live and streams model output back to the client.

## Important backend concepts

- Sessions belong to a single case and user.
- Messages are stored in the database for normal TUM sessions.
- VHB sessions are stored in memory only.
- Live sessions consume a per-session time budget.
- Evaluation is available only for persisted TUM sessions.
